# 開発ルール

このドキュメントでは、MikanSNSを開発する上での基本的なルールを説明します。

---

## 開発技術

大まかな技術構成はREADMEにも載せました。  
実際の開発での各技術の立ち位置は以下の通り

- Next.js                    ：一番の大枠になるワークフレーム。

  - React                    ：Nextに内包されているUI（画面構成）構築のためのライブラリ。

  - TypaScript(言語)         ：Nextアプリを記述するための言語。
    - .tsx                   ：TypeSctiptと、HTMLのようなUI記述の構文を組み合わせた主にReact特有のファイル形式
    - .ts                    ：純粋なTypeScript。UIを生成しない処理に使う。

  - CSS(言語)                ：UIにデザインを施すための言語。色を変えたり大きさを変えたりアニメーションを付けたり。
    - .module.css            ：部品ごとにCSSを分割することのできる魔法の形式。

- Supabase                   ：ログイン認証をしたり、データを管理したりする外部サービス。こちらの整備は管理者がします。
  - Supabase SDK             ：TypeScript上から関数のようにSupabaseとの遣り取りをするための開発キット。こちらは使うかも。

ということで、扱う言語はTypeScriptとCSS、作るものはNext.jsアプリケーションとおぼえておきましょう。

---

## 開発の流れ

このプロジェクトでは機能ごとに開発を進めていくスタンスを取っている。  
(Feature-based Architectureについては[こちら](/docs/architecture.md))  
これはファイル構成だけでなく、仕事分担に関しても同様である。機能を一つずつ整備していくことで全体を作っていきたい。  

実際の流れとしては、

GitHub上でIssueを確認
↓
IssueのAssigneeを自分に設定
↓
Branchを切って開発を開始
↓
諸々の機能を実装
↓
Pull Requestを出して評価、通ったらmainブランチに統合

という流れ。  
(Gitの仕組みや使い方がわからない場合は[こちら](/docs/git.md))

なお、バグや修正事項を見つけた場合には積極的にIssueを立てるようにしましょう。(あるいは管理者に連絡するか)
